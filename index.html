El problema: documentación que cambia, vence y se repite.

Una subcontrata puede tener documentación empresarial, de trabajadores y de maquinaria repartida entre correos, carpetas y plataformas. Docuscala se diseña para ordenar ese flujo sin inventar requisitos ni dar por válido un documento únicamente porque exista.

Vencimientos

Fechas de emisión y caducidad deben quedar identificadas, normalizadas y revisadas.

Contradicciones

Cuando el mismo dato aparece de forma distinta, el sistema debe señalarlo y conservar la evidencia.

Trabajo manual

La automatización se aplica a clasificación, extracción y propuesta de acciones; las decisiones sensibles mantienen control humano.

Cómo funciona

Flujo objetivo de producción. La ejecución concreta sobre Nalanda dependerá de las capacidades oficiales y autorizadas disponibles.

OutlookRecepción controlada de mensajes y adjuntos relevantes.
AnálisisLectura, visión/OCR y clasificación cuando la calidad lo permita.
ValidaciónContraste de datos repetidos, formatos, vigencia e incidencias.
EstructuraConversión a un modelo canónico con evidencia.
NalandaAcciones propuestas: crear, actualizar, mantener, revisar o eliminar.
RevisiónAprobación humana para acciones sensibles, ambiguas o destructivas.

Casos ilustrativos

Caso ilustrativo

Documento con fecha contradictoria

Dos archivos muestran fechas incompatibles para el mismo documento. El resultado no sobrescribe automáticamente: genera una incidencia y solicita revisión.

Caso ilustrativo

Maquinaria sin evidencia suficiente

Se identifica la máquina, pero no consta el documento exigible. El sistema marca el campo como pendiente en vez de completar datos por probabilidad.

Caso ilustrativo

Formación dependiente del oficio

La existencia de un curso se registra, pero su suficiencia se mantiene en revisión hasta verificar oficio, convenio y requisito aplicable.
